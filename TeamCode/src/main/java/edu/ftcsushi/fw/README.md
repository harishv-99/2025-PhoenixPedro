# Sushi framework documentation

The [`Sushi docs home`](<docs/README.md>) is the one complete documentation map.

New to Sushi? [`Set up and verify the project`](<docs/getting-started/Build and Run.md>), then
[`get your first robot driving`](<docs/getting-started/First Sushi Robot Code.md>), then use
[`Build a robot step by step`](<docs/getting-started/Build a Robot Step by Step.md>) as the
build-season course. Open [`Sushi in one picture`](<docs/getting-started/Framework Overview.md>) or
a [`deeper topic`](<docs/getting-started/Beginner's Guide.md>) only when the current checkpoint
needs it. During build
season, keep the [`Sushi Cheat Sheet`](<docs/reference/Sushi Cheat Sheet.md>) nearby and start with
[`Common Problems`](<docs/troubleshooting/Common Problems.md>) when something is not working.

Sushi uses one managed `FtcRobotOpMode`/`RobotProgram` lifecycle, source-driven Plants, one final
drive command path, and fresh single-use Tasks. The
[`Framework Principles`](<Framework Principles.md>) are the design authority for maintainers and
advanced extensions; they are not required before the first-contact guide.
