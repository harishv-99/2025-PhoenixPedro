# Your first mechanism

**Learning mode:** Router

This compatibility URL directs you to the current mechanism lesson or
physical runbook.

This URL is retained for existing bookmarks. The earlier supervised hardware build-along is no
longer the primary Sushi learning route. Choose the destination that matches what you are doing.

## Learn the framework concept

Read [`Plants and hardware`](<learn-sushi/Plants and Hardware.md>) to trace a request from a robot
capability through its mechanism and private Plant to hardware. That chapter uses checked-in source
only; it does not require you to edit an example, enable an OpMode, or own its hardware.

## Validate a physical mechanism

Use the canonical [`Actuator bring-up`](<../testing-calibration/Actuator Bring-up.md>) runbook to
establish a motor or servo direction and, when appropriate, already-backed-off endpoint evidence.
Then follow the
[`production mechanism and timed-behavior check`](<../testing-calibration/Robot Calibration Tutorials.md#production-mechanism-and-timed-behavior-check>)
before relying on the complete mechanism in TeleOp or Auto.

Physical validation is a separate, supervised team activity. A successful build, example
configuration, or conceptual walkthrough is not evidence that real motion is safe.
