# Your first TeleOp

This URL is retained for existing bookmarks. The earlier supervised Starter TeleOp hardware lab is
no longer the primary Sushi learning route. Choose the destination that matches what you are doing.

## Learn the framework concept

Read [`Controls and intent`](<learn-sushi/Controls and Intent.md>) to trace semantic gamepad input
through bindings and robot capabilities, and to see how a robot-centric drive source reaches the
single drivetrain writer. That chapter requires no code changes or robot execution.

## Validate a physical drivetrain

Use the canonical
[`drivetrain direction and integration`](<../testing-calibration/Robot Calibration Tutorials.md#drivetrain-direction-and-integration>)
runbook. It retains the isolated direction checks, neutral-gamepad rule, raised-wheel integration
test, conservative floor progression, STOP checks, and configuration-review boundary from the old
lesson.

Physical validation is a separate, supervised team activity. Do not infer safe directions, braking,
speed limits, or available floor space from the examples.
