# Troubleshooting

Start with what you can observe. Do not change several constants at once, and do not bypass a
Sushi validation just to make an error disappear.

- [`Common Problems`](<Common Problems.md>) — build, Driver Station, controls, Plants, Tasks, drive,
  vision, localization, and Pedro symptoms.
- [`Robot Calibration Tutorials`](<../testing-calibration/Robot Calibration Tutorials.md>) — safe
  physical checks in dependency order.
- [`Sushi Cheat Sheet`](<../reference/Sushi Cheat Sheet.md>) — compare your code with the
  ordinary current API shape.

When reporting a problem, keep the complete exception including its cause, the Driver Station
telemetry message, the OpMode name, the first failing checkpoint, and the smallest relevant config
slice. Those facts are more useful than “it does not work.”
