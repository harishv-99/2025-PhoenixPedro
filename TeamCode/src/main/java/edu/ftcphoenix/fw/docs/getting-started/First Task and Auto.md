# Your first Task and Auto

This URL is retained for existing bookmarks. The earlier supervised timed-intake Auto lab is no
longer the primary Phoenix learning route. Choose the destination that matches what you are doing.

## Learn the framework concept

Read [`Tasks and autonomous`](<learn-phoenix/Tasks and Autonomous.md>) to learn fresh single-use
Tasks, non-blocking sequences, outcomes, cancellation, and the capability vocabulary shared by
TeleOp and Auto. The source walkthrough requires no example edits, deployment, or hardware run.

## Validate timed behavior on a physical mechanism

First qualify the actuator with [`Actuator bring-up`](<../testing-calibration/Actuator Bring-up.md>),
then follow the
[`production mechanism and timed-behavior check`](<../testing-calibration/Robot Calibration Tutorials.md#production-mechanism-and-timed-behavior-check>).
Record the real trial using the [`subsystem experiment`](<../examples/Subsystem Experiments.md>) lab
card when duration, timeout, Task outcome, or operator observation affects the decision.

Physical validation is a separate, supervised team activity. Software timing and passing unit tests
cannot prove clearance, mechanism response, or effective STOP behavior on the robot.
